# UAV Terrain Proto

Прототип полёта над реальным рельефом Украины (Карпаты, район Говерлы, 52×52 км) в Godot 4.6.
Шаг 1 плана «тренажёр/обучающая среда на открытых геоданных» — без единого байта данных Google.

## Источники данных (без ключей и регистрации)

- **Рельеф**: AWS Terrain Tiles (Mapzen terrarium), публичный S3-бакет — высоты декодируются из RGB PNG-тайлов, z13 ≈ 12.7 м/px (исходник SRTM ~30 м).
- **Подложка**: Sentinel-2 L2A из открытого бакета `sentinel-cogs` (AWS Open Data), поиск сцен через Earth Search STAC. Берётся готовый True-Color COG (`visual`/TCI.tif), репроецируется из UTM в Web Mercator под extent DEM и домозаичивается несколькими безоблачными сценами (AOI лежит на границе UTM-зон 34/35). 4096² ≈ 12.7 м/px (нативные 10 м Sentinel-2), unsharp + q95. **Лицензия Copernicus Sentinel — открытая, коммерческое использование разрешено** (указывать источник; см. `attribution` в `meta.json`). Логика — в `tools/s2_albedo.py`.

## Зависимости инструментов (venv)

Пайплайн подложки требует numpy/pyproj/tifffile (без GDAL — pyproj везёт свой PROJ). Один раз:

```bash
python3 -m venv tools/.venv
tools/.venv/bin/pip install numpy pyproj tifffile imagecodecs pillow
```

## Регионы: как добавить/сменить район

Одна команда собирает регион целиком (рельеф + Sentinel-2 + OSM дороги/дома/реки/озёра + запечка + импорт в Godot):

```bash
tools/.venv/bin/python tools/build_region.py --name steppe --lat 47.66 --lon 33.72
./run.sh --region=steppe
```

Регион ложится в `godot/assets/regions/<name>/` (базовый — Карпаты — прямо в `godot/assets/`). Точка старта — `--start lat,lon` (по умолчанию центр). Шаги можно пропускать `--skip osm,water`. Скрипты пайплайна читают `UAV_ASSETS`/`UAV_LAT`/`UAV_LON` из окружения — их можно запускать и по одному. Миссии привязаны к точке старта смещениями, поэтому работают в любом регионе. Второй регион **`steppe`** (47.66, 33.72 — степь Криворожья: Апостолове, поля, лесополосы, сёла — ландшафт, репрезентативный для реального ТВД, в отличие от гор) собран **без рек/озёр** (Overpass-зеркала лежали; дособрать: `build_region.py --name steppe --lat 47.66 --lon 33.72 --skip terrain,osm` — тайлы воды 1–6 уже в кеше). Все самотесты на нём зелёные: `./run.sh --region=steppe --selftest --nosound`.

Тайлы рельефа и скачанные COG'и кешируются в `tools/tile_cache/`. Отладка подложки отдельно: `tools/.venv/bin/python tools/s2_albedo.py --px 1024 --preview`.

## Как запустить

```bash
./run.sh                       # Godot ищется: $GODOT → PATH → /Applications → Sabbath_3D
./run.sh --mode=acro --mission=2 --quality=low
```

**Качество** (клавиша **G**, `--quality=low|medium|high`, запоминается в `user://settings.cfg`): low — рендер-скейл 0.7, без теней/SSR/bloom, лес 1.4 км, 6 фонарей-источников; medium — тени 6 км, без SSR, лес 2.2 км; high — всё (тени 30 км, SSR, лес 3 км, 24 источника). Для школьных ПК начинать с low.

**Экспорт билдов** (`tools/export.sh win|linux|mac|all` → `build/`): пресеты в `godot/export_presets.cfg` (PCK встроен, `*.raw`/`*.json` включены, `height16.png`/`albedo_clean.jpg` исключены). Нужны export templates 4.6.1 (в Godot: Editor → Manage Export Templates → Download; сейчас установлены только web-шаблоны). Вместе с билдом раздавать `ATTRIBUTION.md`.

**Git**: репозиторий инициализирован (кеши `tools/tile_cache`, `osm_cache`, `.venv`, `.godot`, `build/`, `.app` — в `.gitignore`; ассеты `godot/assets` ~60 МБ — в репо, чтобы проект запускался после клона).

## Управление и лётная модель (`flycam.gd`)

**Три режима** (Tab, кнопка Y на геймпаде, `--mode=gps|angle|acro`):
- **GPS** — «как Mavic»: стики задают скорость, отпустил — завис, высота держится; камера — подвес (мышь). Колесо — предел скорости (до 1500 м/с для перелётов по карте, нереалистично).
- **ANGLE** — самовыравнивание: стик = угол наклона (до `tilt`), газ прямой без удержания высоты; камера жёстко на борту с наклоном `cam_tilt`.
- **ACRO** — стик = угловая скорость, выравнивания нет (так учат в FPV-школах).

**Пульт** (mode 2, любой USB-джойстик или RC-передатчик в режиме джойстика): левый стик — газ + рыскание, правый — тангаж + крен. Джойстик перекрывает клавиатуру, когда стик отклонён. Раскладку осей своего пульта смотреть `--joydebug`, менять `--axes=T,Y,P,R` (индексы осей) и `--invert=TYPR` (какие оси инвертировать). Кнопки: Y — режим, X — профиль дрона, RB — буст.

**Клавиатура**: W/S — тангаж, A/D — крен (в GPS — движение), E/Q — газ (в ANGLE/ACRO без клавиш висим с компенсацией наклона), ←/→ или мышь — рыскание, Shift — буст (GPS), ЛКМ — захват мыши / огонь, Esc — отпустить/выход, R — рестарт после краша.

**Профили дронов** (B / `--drone=`): `fpv7` (1.15 кг, T/W 3.2, 560°/с), `fpv5` (0.68 кг, T/W 5.5, 800°/с), `mavic` (0.9 кг, T/W 2.0, наклон ≤35°). Физика ANGLE/ACRO: тяга по оси корпуса, гравитация, сопротивление относительно воздуха (ветер сносит через drag), угловые скорости с откликом моторов `tau`, буфтинг, посадка/взлёт с земли. Интегрирование фиксированным шагом 1/240 с. HUD показывает режим/дрон/источник ввода и индикатор стиков (правый нижний угол). Самотест: `--flytest` (висение, падение без газа, отклик ACRO/ANGLE, снос ветром, мягкая посадка).

Debug-флаги (после `--`): `--screenshot` (кадр в shot.png и выход), `--topdown` (вид сверху), `--unshaded`, `--uvdebug`, `--nofog`.

## Миссии, скоринг, телеметрия и реплей

**Миссии** (`scripts/mission.gd`, клавиша **N** — следующая, `--mission=N`): 1 «Взлёт — коридор — посадка» (ANGLE, 5 ворот + площадка), 2 «Слалом ACRO» (8 низких ворот), 3 «Разведка за хребтом» (точка выбирается автоматически там, где LOS от оператора минимален; удержание 5 с; вернуться и сесть), 4 «Ударный заход» (танк + БТР спавнятся у дороги в 900 м, уничтожить, вернуться). Шаги заданы смещениями от точки старта по курсу дрона → миссии переносимы на любой регион. Старт — с земли на свободной площадке (`_clear_spot`), режим полёта выставляется рекомендованный. Скоринг: 100 − (время сверх норматива)/2 − 15 за пропуск ворот − 20 за краш; батарея 0 → провал. Результат — на экране и в `user://results/results.csv`. Самотест `--missiontest`.

**Телеметрия** (`scripts/telemetry.gd`): всегда пишется `user://flights/flight_<дата>.csv` (10 Гц: позиция, AGL, скорость, углы корпуса, газ, режим, стики, RSSI, батарея, события: mission_start/step_done/gate_missed/crash/kill/mission_end). Путь печатается при старте и выходе (macOS: `~/Library/Application Support/Godot/app_userdata/UAV Terrain Proto/`).
**Реплей**: `--replay=<файл.csv>` (или имя из `flights/`) — дрон ведётся по записи с интерполяцией, ввод отключён; пробел — пауза, ←/→ ±5 с, `[`/`]` — скорость. События показываются в момент их наступления. Это основа для «разбора полёта» с инструктором.

## Слой OSM (дороги, дома, реки, лес)

- `tools/fetch_osm.py` / `tools/fetch_water.py` — Overpass (5 зеркал, ретраи, кеш в `tools/osm_cache/`): 8044 дороги, 32 712 зданий, 3043 водотока.
- `tools/bake_overlay.py` — запекает реки и дороги (AA-слой с блюром) в albedo.jpg, строит `mask.png` 2048² (1 = лес по порогу яркости RGB≤85 — калибровано по этому снимку).
- Дома: MultiMesh-коробки по реальным footprint'ам OSM (центр, габариты, угол, высота из тегов).
- Деревья: `scatter.gd` — стриминг чанков 512 м в радиусе 3 км, ~420 попыток/чанк по маске леса, сид от координат чанка. **5 видов** (ель/сосна/лиственное/берёза/куст) с весами + per-instance вариация цвета кроны и размера; бакетятся по типу в отдельные MultiMesh на чанк.

## Цели, поражение, ответный огонь, РЭБ

- `scripts/targets.gd` — танки, БТР и группы пехоты (низкополигональные, из примитивов) патрулируют **реальные дороги OSM** туда-обратно; спавн в кольце 0.6–4 км от камеры, деспаун за 5.5 км, до ~18 техники + 6 групп пехоты. `spawn_near(pos, kinds)` — для миссий.
- **Поражение — сброс боеприпаса с баллистикой** (ЛКМ при захваченной мыши; боекомплект 6, перезарядка 1.2 с): начальная скорость = скорость дрона, гравитация, сопротивление относительно воздуха (ветер сносит), взрыв при касании земли или прямом попадании; радиус поражения 7 м (пехота ×1.3). Нужно брать упреждение (с 80 м при 20 м/с вынос ~75 м). Таран корпусом < 8 м (ударный FPV) засчитывается всегда. Hitscan убран.
- **Реакция целей**: при обнаружении дрона (техника 420 м, пехота 250 м, дрон ниже 220 м AGL) техника уходит на ×2.4 скорости, пехота сходит с дороги в укрытие и залегает.
- **Ответный огонь** (`--noaa` — выключить): БТР (автопушка) и танк (ЗПУ) до 450 м, пехота до 120 м, только при прямой видимости через рельеф; очередь раз в 1.6/2.5 с, вероятность попадания растёт вблизи, при малой скорости дрона (висение!) и ниже 120 м. Попадание → краш «зенитный огонь». Трассеры видны.
- **РЭБ** (`scripts/ew.gd`, `--nojam` выкл., `--hidejam` скрыть купола): 3 постановщика в 1.2–2.5 км от старта (детерминированно от `--seed`), радиус 500–800 м, полупрозрачные купола. Внутри RSSI падает к центру (до 5%). При канале < 50% стики ослабевают и шумят, < 10% — **failsafe** (стики в ноль: GPS висит, ANGLE ровняется, ACRO — неуправляем). HUD: «Канал: N%», расстояние до ближайшей зоны, «⚠ РЭБ: подавление N%», «✖ FAILSAFE».
- Debug: `--targetdebug` спавнит танк+БТР+отделение в 350 м перед стартовой камерой. Тесты: `--selftest` (баллистика: время падения с 80 м, вынос, поражение; РЭБ: jam_factor).

## Погода и физика дрона

- `scripts/weather.gd` — 5 пресетов (день / облачно+ветер / дождь-шторм / закат / ночь): солнце, ambient, небо, туман, тон, дождь (GPUParticles, 2400 капель, следует за камерой), ветер (сносит дрон и наклоняет дождь), молнии в шторм. Клавиши 1-5 и P (цикл). Флаг `--weather=N`.
- `scripts/flycam.gd` — дрон с инерцией: разгон/выбег (ACCEL/DRAG), крен в вираж, наклон носа от ускорения, вибрация винтов (растёт на ветру), снос ветром. Колесо — предел скорости, Shift ×3.5.
- Модели целей (`targets.gd`): **танк** (тип Т-72/Т-90: корпус со скошенным лбом, блоки ДЗ на глясисе и башне, литая 8-гранная башня `_oct_turret`, ствол с эжектором+кожухом+казёнником, 6 катков + гусеничные ленты с траками, командирская башенка с ЗПУ, корзина ЗИП, бочки на корме, 2 антенны, хаки), БТР (8 колёс, гранёный корпус, автопушка), пехота (каска, рюкзак, автомат); техника прижата к рельефу по нормали склона (крен ограничен), пехота покачивается при ходьбе.

## Детализация земли (detail texturing)

Спутник 10 м/px вблизи размывается в «пятно». Решение в `terrain.gdshader`:
- спутник даёт крупную раскладку (поля/лес/дороги), поверх — 4 частоты процедурной фактуры травы/грунта (`_make_ground_detail`) + высотный шум (`_make_detail_noise`), проявляются у камеры (`detail_range` 1200 м);
- возмущение нормали высотным шумом в мировом пространстве (без тангенсов) даёт светотень микрорельефа;
- камень на крутых склонах по нормали (где спутник размазан в зелень);
- **ключевое**: анизотропная фильтрация детальных сэмплеров (`filter_linear_mipmap_anisotropic`) + `anisotropic_filtering_level=16` в project.godot — иначе под скользящим углом мипы съедают фактуру вдаль.

## Звук (процедурный, без аудиофайлов)

`scripts/sound.gd` — весь звук синтезируется в рантайме:
- **моторы + ветер**: AudioStreamGenerator, real-time. 4 слегка расстроенных винта (биения) + высокий вой (4-я гармоника) + широкополосный шум; тон и громкость растут с газом (скоростью). Свист ветра — сглаженный шум по скорости и силе ветра погоды.
- **взрыв**: заранее синтезированный AudioStreamWAV (нисходящий рокот + затухающий шум), проигрывается через пул из 6 AudioStreamPlayer3D — позиционный, с затуханием по дальности. Вызов из `targets._kill`.
- **выстрел**: короткий WAV, 2D, из `targets.fire`.
- Отключается флагом `--nosound` (и не грузится при `--screenshot`).

## Реальные текстуры (CC0)

`tools/fetch_textures.py` качает с **Poly Haven** (лицензия **CC0** — public domain, коммерческое/оборонное использование без атрибуции) в `godot/assets/tex/`:
- земля: `aerial_grass_rock` (трава), `aerial_mud_1` (грунт), `aerial_rocks_04` (скала) — albedo + normal;
- дома: `grey_roof_01` (черепица), `beige_wall_001` (штукатурка).

Земля (`terrain.gdshader`): трава на пологих, камень на склонах (по нормали), грунт на «бурых» пятнах спутника; фото-фактура принимает крупный цвет спутника (реальная раскладка полей/леса); 2 масштаба тайлинга с поворотом на 40° гасят повтор; карты нормалей дают рельеф.
Дома (`_build_buildings` + `facade.gdshader`): единый MultiMesh со **процедурным фасадом** — окна реального размера сеткой (колонки ~3.2 м, по этажам, подоконник ~1 м), дверь только на переднем длинном фасаде, цоколь-фундамент. Габариты стены приходят per-instance (`INSTANCE_CUSTOM`=w,h,d,type), поэтому окна не растягиваются. **Случайная вариация по дому** (хеш от `INSTANCE_ID`): ставни/без и их цвет, цвет двери, окошко в двери. **Свет в окнах** через `EMISSION`, доля `lit_amount` растёт к ночи (0.02 день … 0.6 ночь) — задаётся из `weather.gd` по пресету. 4 типа (хата/дом/сарай/ПГТ) задают цвет стен и тип крыши (двускатная PrismMesh / плоская); трубы отдельной MultiMesh.

Текстуры Google/спутника сюда **нельзя** (лицензия+нет покрытия UA) — CC0 чист для Brave1/NEWOYA.

## Объёмные дороги (3D-полотно)

`scripts/roads.gd` — из OSM-линий (`roads.json`) строит ленту-полотно по рельефу: ресемплинг вдоль дороги (шаг 6 м, следует за высотами), ширина по классу, приподнято на 0.15–0.22 м. Два материала: **асфальт** (`asphalt_02`, трассы/улицы/service) и **гравий** (`gravel_road`, track) — CC0 Poly Haven, normal maps, cull disabled. Батчится в 2 ArrayMesh. ~1.4M вершин, строится ~1.6 с. Запечённые в текстуру линии остаются для дальнего плана.

## Придорожные объекты (фонари, столбы)

`scripts/props.gd` — вдоль OSM-линий расставляет с равным шагом: **уличные фонари** (27k, вдоль улиц, шаг 42 м) — столбик + вынос + светящийся плафон (emissive, накал растёт к ночи через `set_window_light` вместе с окнами), и **столбы ЛЭП** (68k, вдоль дорог покрупнее, шаг 55 м) — опора + две траверсы. Всё MultiMesh, строится ~150 мс. **Живой свет ночью**: пул из 24 OmniLight3D прилипает к ближайшим к камере фонарям (радиус 300 м, обновление 0.3 с), даёт тёплые пятна света на дорогах/домах; днём выключен. Накал фонарей и пула завязан на `set_window_light` вместе с окнами.

## Атмосфера (туман, дым, провода)

- **Туман в низинах**: высотный туман Environment (`fog_height`/`fog_height_density`) заполняет долины ниже линии гребней; включается в пресетах заката/дождя/ночи (`weather.gd`) — на закате получается «море тумана».
- **Дым из труб** (`scripts/smoke.gd`): ~40% труб дымят; пул из 10 GPUParticles3D прилипает к ближайшим к камере трубам (радиус 260 м), мягкая круглая текстура-клякса, подъём + снос ветром погоды.
- **Провода ЛЭП** (`props.gd` `_wire`): соседние столбы вдоль дороги соединены провисающими линиями (PRIMITIVE_LINES, catenary-провис), один тонкий mesh.

## Небо и bloom

`scripts/sky.gdshader` (shader_type sky) — градиент + процедурные плывущие облака (fbm-шум, сносятся ветром/временем), диск солнца с ореолом, звёзды ночью (точки по редким ячейкам). Цвета/покрытие/цвет облаков/направление солнца/флаг ночи задаёт `weather.gd` per-preset (`cov`/`ccol`/`cdark`). Заменил ProceduralSkyMaterial на ShaderMaterial.
Bloom: `env.glow_enabled` (additive, threshold 1.0) — светятся окна, фонари, солнце, закат. Ключевой grabli: звёзды нельзя рисовать заливкой ячейки `smoothstep(hash(floor))` — выходят белые квадраты; нужна точка (расстояние до случайной позиции внутри ячейки).

## Вода, качание деревьев, FPV

**Вода** (`water.gd` + `water.gdshader`): реки/ручьи из `water.json` лентами (высота = минимум рельефа поперёк русла + сглаживание вдоль, иначе вода скачет по грубой сетке), водоёмы из `lakes.json` (`fetch_lakes.py`, 97 шт.) плоскими полигонами через `Geometry2D.triangulate_polygon`. Шейдер: две движущиеся волновые сетки → нормали, френель (к горизонту зеркальнее), блики на гребнях. Отражения: `env.reflected_light_source = SKY` + SSR.
*Грабли*: рельеф 51 м/узел не разрешает котловины горных озёр — центр часто ВЫШЕ берега, плоское зеркало тонет. Ставим воду поверх внутреннего «горба» (`max` по внутренним пробам + 0.35), ограничив подъём 9 м.

**Качание деревьев** (`tree.gdshader`): смещение вершин ∝ (высота над комлем)², фаза от мировой позиции инстанса (лес качается волной), направление/сила из `weather.wind_vec()`; `scatter.gd` обновляет параметры раз в 0.2 с. `base_color` на сабмеш × instance color = вариация крон сохранена.

**FPV-подача** (клавиша **F**): `fpv.gdshader` — бочкообразная дисторсия (рыбий глаз), виньетка, хроматические аберрации, строчная структура, зерно, срывы строк при слабом сигнале; FOV 105°. `fpv_osd.gd` — зелёный OSD: авиагоризонт (крен/тангаж), шкалы скорости и AGL, батарея (~10 мин), RSSI (падает с дальностью от точки взлёта → картинка сыпется), таймер + REC, HDG, дистанция HOME. Обычный HUD скрывается.

## Симуляция: коллизии, LOS-сигнал, сид, лётная модель

- **Коллизии и краш** (`main.gd` + `flycam.gd`): пространственная сетка препятствий 64 м — коробки зданий (`col_add_box`, повёрнутый point-in-rect), цилиндры столбов/фонарей (`col_add_cyl`), деревья по чанкам (`col_register_trees` из scatter, снимаются при выгрузке). `check_crash(pos)` сканирует 3×3 ячейки. Удар о дом/столб/дерево или о землю на скорости (>14 м/с вниз) → `crash()`: дрон падает, заваливается набок, FPV в статику; **R** — рестарт с точки взлёта. Самотест `--coltest`.
- **Сигнал по прямой видимости** (`los_factor` + `fpv_osd.gd`): луч оператор→дрон трассируется через рельеф; макс. «утопание» линии под землю → падение RSSI (40 м перекрытия = полная потеря). За горой сигнал рвётся даже вблизи; проверено (вверх 1.00, за хребтом 0.00).
- **Фиксированный сид** (`seed(hash(sv))` в начале `_ready`, флаг `--seed=N`): расстановка и движение целей повторяются — нужно для разбора «того же полёта».
- **Лётная модель** (`flycam.gd`): горизонталь и вертикаль раздельно. Гравитация (12 м/с²) + тяга винтов с авто-зависом (база компенсирует g, E/Q добавляют); падает быстрее, чем лезет (`CLIMB_MAX`). Ветер = снос + турбулентный буфтинг по осям, растёт в порывах.

## Архитектура

- `godot/scripts/main.gd` — оркестратор: регион/данные (`asset_path`), террейн-меш (кеш в user://), дома, окружение, качество, крах/рестарт, тонкие обёртки над коллизией. `height_at` — высота ПО МЕШУ.
- `collision.gd` — сетка препятствий 64 м (здания/столбы/деревья), `check_crash`, `los_factor` (радиовидимость через рельеф).
- `flycam.gd` — дрон: ввод (пульт/клавиатура/мышь), режимы GPS/ANGLE/ACRO, профили, физика, `--flytest`.
- `hud.gd` — всё поверх 3D: строки, маркеры целей/миссии, ветрометр, стики, FPV-слой (`fpv.gdshader` + `fpv_osd.gd`), краш/результат/реплей.
- `mission.gd` — упражнения (ворота/посадка/разведка/удар), скоринг, `results.csv`, `--missiontest`. `telemetry.gd` — запись CSV 10 Гц + события, реплей `--replay=`.
- `terrain.gdshader`, `facade.gdshader`, `sky.gdshader`, `water.gdshader`, `tree.gdshader` — материалы. `scatter.gd` (лес), `roads.gd`, `props.gd` (фонари/ЛЭП/живой свет), `water.gd`, `smoke.gd`, `targets.gd`, `weather.gd`, `sound.gd`, `windflag.gd`, `sticks.gd`.
- `selftest.gd` — `--selftest` (height_at на узлах, lat/lon-обратимость, коллизии+LOS, лётная модель, миссии) → код выхода 0/1. `debug.gd` — `--screenshot`/пресеты кадров/`--targetreport`.
- `tools/` — Python-пайплайн данных; `tools/build_region.py --name X --lat --lon` собирает регион в `godot/assets/regions/X/`, запуск `./run.sh --region=X`.

## Грабли, на которые уже наступили (не повторять)

1. **Порядок обхода треугольников**: в Godot фронтальные грани — по часовой стрелке при взгляде на лицевую сторону; неправильный winding = террейн виден только «полосками» на крутых склонах (backface culling), а «земля» процедурного неба маскирует дыру под привычный ландшафтный цвет.
2. **ProceduralSkyMaterial ground_bottom_color** по умолчанию бурый — при отладке невидимой геометрии выглядит как «рельеф без текстуры». Ставьте дымку.
3. 16-бит PNG heightmap при рантайм-загрузке Godot режет до 8 бит — поэтому высоты идут отдельным `height.raw`.
4. **`height_at` должен совпадать с сеткой террейн-меша**, а не с детальной картой высот. Меш строится по грубой сетке MESH_RES (1024²), а карта высот — 4096². Если `height_at` брать билинейно по 4096², между узлами меша поверхности расходятся на склонах → дороги/фонари уходят ПОД видимый рельеф, а камера (клампится по `height_at`) проваливается под террейн и показывает изнанку. Решение: `height_at` семплит те же узлы, что и построение меша (`_node_h`, ближайший пиксель на сетке MESH_RES).
5. Runtime `Image.load_from_file` для albedo не нужен — редакторный импорт (`load("res://assets/albedo.jpg")`) даёт корректные mip'ы и sRGB.
